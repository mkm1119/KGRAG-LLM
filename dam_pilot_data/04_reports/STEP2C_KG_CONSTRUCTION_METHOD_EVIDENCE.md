# KG 구축 절차의 근거 문헌과 우리 데이터 적용

- 작성일: 2026-10-08
- 근거 확인 방식: 저장소 PDF(DDKG, OntoDSMS, GraphAide)와 업로드된 Zhang 2025 PDF의 본문을 텍스트로 추출해 읽었다. 그림과 표의 이미지는 보지 못했다. 교수님 개념 정리 PDF(「Urban Flood Ontology–KG 지식 시스템 중간 정리」)는 13쪽 파이프라인을 인용한다.
- 쪽·절 번호는 추출 텍스트 기준이며, 인용 전에 원문 대조가 필요하다.

## 1. 문헌이 제시하는 구축 방식

| 문헌 | 구축 방식 (본문 근거) |
|---|---|
| **DDKG** (Huang 2026) | §3.2.1 자료를 **구조화 표**(관리 플랫폼의 표 → 상위 클래스 Dam, Properties, Location, Parameter)와 **비정형 텍스트**(→ HazardForm, HazardComponent, SafetyEvaluation)로 나눈다. 텍스트는 마크다운 변환, OCR, 정규식으로 블록 분리 후 사용. §3.2.2 규칙 기반 추출, §3.2.3 LLM 기반 추출(온톨로지 분류 프레임워크 OHCF), §3.3 추출 결과를 JSON으로 모으고 스크립트로 Cypher를 만들어 Neo4j에 일괄 적재 |
| **OntoDSMS** (Zhou 2023) | 관계형 DB와 온톨로지의 매핑을 D2RQ의 **가상 RDF 그래프**로 구현. 데이터를 복제하지 않고 SPARQL로 접근. 규칙 추론기와 확장 SPARQL |
| **GraphAide** (Purohit 2024) | 온톨로지를 입력으로 주어 **LLM의 응답 스키마를 제한**하며 비정형 텍스트에서 KG 생성. 개체명 추출, 관계 추출, **개체 중의성 해소(disambiguation)**, KG 인코딩, KG 유지보수 단계. Pydantic으로 생성 서브그래프의 일관성 검증 |
| **Zhang** (2025) | §3.1 표준·매뉴얼·논문·웹 문서를 수집하고 OCR 후 문서·문장·단어 수준으로 걸러 정제, 텍스트 분석으로 온톨로지 구축. §3.2 개체·관계 동시 추출(PFKAN), 추출 성능을 F1로 평가. §3.3 질문 의도 파싱(규칙+지도학습+LLM 투표)으로 KG 검색 |
| **교수님 개념 정리** (p.13) | 원자료 → 데이터 매핑 → 개체 추출 → 개체 해소 → 개체 연결 → 속성·관계 추출 → 정규화 → **온톨로지 검증** → KG 구축. 온톨로지는 KG 생성의 "semantic contract" |

## 2. 우리 적용 절차와 현재 상태

| # | 단계 | 근거 | 우리 데이터에서 할 일 | 상태 |
|---|---|---|---|---|
| 1 | 소스를 구조화 / 비정형으로 구분 | DDKG §3.2.1 | 승인 CSV, 측정 시간자료, 별표3 표는 구조화. 규정 조문, 승인 비고, (승인 사유)는 비정형 | 정리 필요 |
| 2 | 전처리 | DDKG §3.2.1, Zhang §3.1 | 인코딩(cp949), 날짜·시각 표기, 측정 시각 라벨, 시설 코드·이름 정규화. 규정 XML을 조문·별표로 분할 | 부분 수행 |
| 3 | 구조화 자료 매핑 | OntoDSMS, DDKG §3.2.1 | Dam, HydrometeorologicalState, Approval, Criterion을 규칙으로 매핑 | 수행 (KG v2) |
| 4 | 비정형 텍스트에서 지식 추출 | DDKG §3.2.2·3.2.3, Zhang §3.2, GraphAide | (a) 승인 비고 → Operation (규칙 기반, 수행), (b) 규정 조문 → 규칙·조건, (c) 승인 사유 텍스트 → 사유 유형 | (a)만 수행 |
| 5 | 개체 해소·연결 | GraphAide, 교수님 p.13 | 승인 "충주", 측정 "충주댐", 별표3 "충 주 댐"을 같은 Dam으로 연결하는 근거 기록 | 이름·코드 일치만 사용, 근거 문서화 필요 |
| 6 | 정규화와 온톨로지 검증 | 교수님 p.13, GraphAide(스키마 검증) | 허용 관계 쌍, 필수 속성, 값 형식, 시간 형식 검증 | **미수행** |
| 7 | 저장 | DDKG §3.3, OntoDSMS | 현재 CSV. Neo4j(DDKG) 또는 가상 매핑(OntoDSMS)을 쓸지 결정 | 결정 필요 |
| 8 | 추출 평가 | DDKG, Zhang(F1 보고) | 비고 분류 정확도, 사유 분류 정확도를 사람이 검토한 표본으로 측정 | **미수행** |

## 3. 문헌과 비교한 우리 구축의 빈틈

- **추출 정확도를 측정하지 않았다.** DDKG와 Zhang은 추출 결과를 F1로 평가한다. 우리 비고 분류는 규칙을 만든 사람이 직접 훑어봤을 뿐이다.
- **온톨로지 검증 단계가 없다.** 교수님 파이프라인과 GraphAide는 생성 결과를 스키마로 검증한다.
- **비정형 지식 추출이 비고 분류 하나뿐이다.** DDKG와 Zhang의 KG는 비정형 텍스트에서 지식을 뽑는 것이 중심이다.
