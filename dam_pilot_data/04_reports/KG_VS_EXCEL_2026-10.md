# KG 방식과 엑셀 방식 비교: LLM에게 주어지는 것은 무엇이 다른가

- 작성일: 2026-10-08
- 비교 대상: 같은 원자료(5개 댐)를 (A) 엑셀 시트로 LLM에 주는 경우, (B) KG와 시각 기반 검색으로 근거 묶음을 만들어 주는 경우
- 엑셀 방식 재현: `04_reports/excel_baseline_5dams.xlsx` (생성: `scripts/step3c_excel_baseline.py`). 이 환경에서는 Excel/LibreOffice로 열어 보지 못했고, 파일 구조와 시트 내용은 XML로 검증했다.
- 수치: `03_normalized/step3c_excel_vs_kg_stats.csv`

## 1. 결론

- **정보의 양은 같다.** KG는 같은 원자료에서 규칙으로 만든 것이라 엑셀에 없는 정보를 새로 만들지 않는다.
- **다른 것은 연결·해석을 누가 언제 하느냐이다.** 엑셀 방식은 LLM이 질문마다 하고, KG 방식은 구축할 때 한 번 하고 검색 코드가 한다.
- **이번 테스트(댐 5개, 승인 102행)에서 KG가 엑셀보다 낫다는 것은 입증되지 않았다.** 승인 목록 질문(Q03, Q11)에서는 엑셀 방식이 낫다.

## 2. 엑셀 방식에서 LLM이 받는 것

| 시트 | 행 | 특징 |
|---|---|---|
| 승인_원본 | 102 | 원본 컬럼 그대로. 승인일은 날짜만, 방류시작은 시각 포함, 비고는 자유 문장 |
| 제한수위_별표3 | 9 | 댐 이름이 "충 주 댐"처럼 공백이 들어 있음. 코드 없음 |
| 규정_조문 | 23 | 조문·별표 원문 |
| 측정_시간자료 | 251,963 | 5개 댐 시간자료 전체. 한 번에 프롬프트에 넣을 수 없음 |

엑셀 상태 그대로의 불편한 점:
- 시설 이름이 시트마다 다르다: 승인 "충주", 제한수위 "충 주 댐", 측정 "충주댐". 승인과 측정은 코드가 같지만 제한수위·규정에는 코드가 없다.
- 운영행위 구분이 없다. 비고를 읽고 판단해야 한다.
- 어느 시각의 측정값을 볼지 정해 주는 열이 없다. 측정 시각은 01~24시 표기이고 의미가 확정되지 않았다.

## 3. 일을 누가 하는가

| 일 | 엑셀 방식 | KG 방식 |
|---|---|---|
| 시설 연결 (이름·코드) | LLM이 질문마다 맞춤 | 구축 때 한 번 (Dam 개체와 `appliesToDam`) |
| 운영행위 파악 | LLM이 비고를 읽고 판단 | 구축 때 규칙으로 분류 (Operation) |
| 시점 창 선택 | LLM이 시각을 읽고 필터 (또는 코드 작성) | 검색 코드가 운영행위 시각의 -6~+12시간 |
| 제한수위와 비교 계산 | LLM이 계산 | 검색 단계가 계산해 묶음에 포함 |
| 근거 위치 표시 | 행 번호나 시트명을 LLM이 언급 | 개체마다 근거 ID와 위치가 붙음 |
| 승인 전체 파악 | 시트 전체를 보면 누락 없음 | Operation이 없는 승인 38건은 Dam에서 도달 불가 |
| 한계 안내 | LLM 판단에 의존 | 묶음에 유의 문구를 넣음 |

## 4. 질문별 비교

엑셀 방식의 입력 크기는 질문에 필요한 시트만, 측정 시트는 해당 댐의 3일치만 골라 준 경우의 글자 수이다(실제 엑셀 전체는 측정 251,963행).

| 질문 | 필요한 시트 | 엑셀 입력(글자) | KG 묶음(글자) | 차이 |
|---|---|---|---|---|
| Q01 충주댐 제한수위 | 제한수위 + 규정 | 2,933 | 2,586 | 거의 같음. 엑셀은 "충 주 댐" 표기를 읽어야 함 |
| Q02 소양강댐 2020-08 운영행위 | 승인 | 8,688 | 128 | 엑셀에는 승인 2건이 보이고 KG에는 운영행위 1건. 어느 쪽이 맞는지는 운영행위 정의에 달림 |
| Q03 충주댐 2020-08 승인 | 승인 | 8,688 | 289 | **엑셀은 승인 3건 모두, KG는 1건** |
| Q04 소양강댐 당시 상태 | 승인 + 측정 | 9,828 | 3,635 | KG가 상태·기준·근거를 함께 줌 |
| Q05 충주댐 수위 vs 제한수위 | 승인 + 측정 + 제한수위 + 규정 | 12,761 | 3,643 | 엑셀은 4개 시트를 잇고 직접 계산해야 함 |
| Q06 횡성댐 승인과 상태 | 승인 + 측정 | 9,828 | 7,096 | 운영행위 2건의 같은 상태값이 반복되어 KG 묶음이 커짐 |
| Q10 횡성댐 2017 당시 수위 | 승인 + 측정 | 8,688 | 2,923 | 둘 다 측정 자료 없음 → 확인 불가 |
| Q11 광동댐 2021-07 승인과 방류량 | 승인 + 측정 | 13,008 | 123 | **엑셀은 승인 3건과 측정 72행으로 답 가능, KG는 0건** |
| Q07 하류 댐 수위 | - | - | - | 엑셀에도 상하류 정보가 없어 LLM이 지리 지식으로 답할 위험 |
| Q08 방류 이유 | - | - | - | 엑셀에도 사유가 없어 LLM이 비고로 이유를 추정할 위험 |
| Q09 감소방류 | 승인 | 8,688 | - | LLM이 비고 102행을 직접 훑어야 함 |

## 5. 정직한 해석

- **이 규모에서는 입력 크기 차이가 작다.** 승인 시트 전체가 8,688자이다. 크기 이점은 측정 자료가 큰 질문(Q04~Q05)에서만 나타난다.
- **KG의 운영행위 분류는 엑셀에 열 하나를 추가해도 같은 효과를 낼 수 있다.** 시설 코드 열을 추가하는 것도 마찬가지다. 그래서 KG만의 고유한 이점은 "여러 단계 관계를 따라가는 질문"에서만 나오고, 이번 질문들은 대부분 1~2단계였다.
- **KG의 단점:** 구축 때 한 해석(분류 규칙, 연결)이 고정되어 오류가 질문 전체로 퍼진다. 구조 때문에 승인이 누락된다(Q03, Q11).
- **KG의 이점이 될 수 있는 것(미입증):** 연결을 한 번 만들어 재사용, 모든 항목의 근거 ID, 데이터가 커질 때 필요한 부분만 전달, 출처가 추가될 때 확장.

## 6. 공정한 비교 실험 (다음 단계)

같은 질문 11개를 격리된 LLM으로 두 조건에서 돌린다.

| 조건 | LLM 입력 |
|---|---|
| E (엑셀) | `excel_baseline_5dams.xlsx`에서 질문에 필요한 시트 + 해당 댐 3일치 측정 행 |
| K (KG) | `step3b_bundles.md`의 질문별 근거 묶음 |

평가 항목: 정답 항목 회수율, 인용한 근거의 정확성, 한계 표기, 외부 지식 사용 여부(Q07), 근거 없는 수치.
