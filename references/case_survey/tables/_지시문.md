# 비교표 행 만들기 지시문

최종보고서의 사례 비교표를 만들기 위한 작업이다. 배정받은 묶음의 논문마다 사실 정리 파일(/home/user/KGRAG-LLM/references/case_survey/facts/<이름>.json)을 읽고, 표에 넣을 짧은 행으로 줄인다.

## 지켜야 할 것
- 사실 정리 파일에 적힌 내용만 쓴다. 새로 지어내거나 일반 지식으로 채우지 않는다. 사실 정리에 "본문에 없음"이면 표에는 "-"로 쓴다.
- 뜻이 불확실하면 원문 글(/home/user/KGRAG-LLM/references/case_survey/txt/ 또는 txt_add/ 의 같은 이름 .txt)에서 해당 부분만 찾아 확인한다. 확인할 수 없으면 "-"로 쓴다.
- 한국어 명사형으로 짧게 쓴다(문장 부호 최소화, "~함/~임" 어미 금지, 예: "점검 문서 4,292건"). 모델·데이터셋·지표 이름은 원문 표기.
- 글자 수 한도(공백 포함)를 반드시 지킨다.
- tags의 값은 아래에 주어진 낱말 가운데에서만 고른다.

## 출력
파일: /home/user/KGRAG-LLM/references/case_survey/tables/<묶음 이름>.json — 아래 객체의 배열(묶음 목록의 순서대로)

```json
{
 "id": "사실 정리 파일 이름(.json 제외)",
 "case": "사례 이름(시스템·모델 이름이 있으면 그것, 없으면 내용을 나타내는 짧은 이름, 20자 이내)",
 "source": "제1저자 성 외(연도) 형식. 저자가 2명 이하면 모두. 국내 논문은 한글 이름(예: 민기단 외(2025))",
 "venue": "게재처 이름(40자 이내)",
 "venue_type": "학술지 | 학술대회 | 사전 공개본 | 기타",
 "country": "국내 | 해외 (국내 = 한국 기관 저자의 한국 학술지 논문)",
 "domain": "대상 분야와 적용 대상(25자 이내)",
 "data": "사용 자료의 종류와 규모(45자 이내)",
 "method": "구조·방법의 핵심(70자 이내)",
 "knowledge": "지식 구조: 온톨로지·KG 사용 여부와 구축 방식(35자 이내). 안 쓰면 '사용 안 함'",
 "retrieval": "검색 방식과 저장소(40자 이내). 없으면 '-'",
 "llm": "실제로 쓴 생성 모델과 규모(35자 이내). 없으면 '사용 안 함'",
 "finetune": "미세조정 방식(20자 이내). 안 하면 '안 함'",
 "deploy": "운영 환경(25자 이내): 로컬·폐쇄망·클라우드 API 등. 없으면 '-'",
 "eval": "평가 방법과 자료 규모(45자 이내)",
 "result": "대표 결과 한 가지를 수치와 함께(60자 이내)",
 "limit": "저자가 밝힌 한계 한 가지(50자 이내). 없으면 '-'",
 "tags": {
   "water": "댐·수리시설 | 홍수 | 수문·수자원 일반 | 수자원 외",
   "knowledge_type": "온톨로지+KG | KG | 온톨로지 | 없음",
   "kg_build": "수작업·규칙 | 전통 NLP 모델 | LLM 추출 | 혼합 | 해당 없음",
   "retrieval_type": "벡터 | 희소+벡터 | 그래프 질의 | 그래프+벡터 | 도구 호출 | 없음",
   "llm_type": "상용 API | 공개 모델 로컬 | 둘 다 | 사용 안 함 | 불명",
   "finetune_type": "LoRA 계열 | 전체 미세조정 | 추가 사전학습+미세조정 | 안 함",
   "eval_type": "자동 지표 | 전문가 평가 | LLM 평가 | 자동+전문가 | 자동+LLM 평가 | 정성 시연 | 평가 없음",
   "study_type": "시스템 구축 | 모델 개발 | 벤치마크·평가 | 방법 제안 | 조사·전망"
 }
}
```

끝나면 쓴 파일 경로, 행 수, 확신이 없어 "-"로 둔 칸이 많았던 논문을 보고한다.
