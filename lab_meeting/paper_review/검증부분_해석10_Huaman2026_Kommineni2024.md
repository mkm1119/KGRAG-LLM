# 검증 부분 해석 10: 최신 논문 두 편 (Huaman 2026, Kommineni 외 2024)

2026-11-18 작성. 두 편 모두 전문을 읽었다. 5장은 논문 내용이 아니라 내가 우리 연구에 대어 본 것이다.

# 1부. Huaman (2026): KG 품질 평가의 차원 24개

## 0. 먼저 알아 둘 것

- **논문.** Huaman, E. (2026). Knowledge Graphs Quality Assessment in the Era of LLMs: A Conceptual Framework. arXiv:2610.31684v1 (2026년 10월 3일). 8쪽, 참고문헌 25편.
- **성격.** 제목 그대로 "개념 틀"이다. 차원과 질문을 표로 정리하고 점수를 합치는 방법을 제안했다. **실제 KG에 적용한 결과는 없다.** 결론에서 "특정 사례에서 평가되어야 한다"고 향후 과제로 남겼다.
- 심사를 거쳤는지는 원고에 나와 있지 않다.

## 1. 품질 차원이 어떻게 이어져 왔나 (표 1)

이 논문에서 가장 쓸모 있는 부분이다. 품질 차원을 정리한 문헌 아홉 편을 시간순으로 비교했다.

| 문헌 | 대상 | 차원 수 |
|---|---|---|
| Wang·Strong (1996) | 데이터 | 15 |
| Naumann·Rolker (2000) | 정보 | 22 |
| Bizer (2007) | 정보 | 16 |
| Zaveri 외 (2016) | 링크드 데이터 | 18 |
| Färber 외 (2018) | 링크드 데이터 (DBpedia, Wikidata 등에 실제 적용) | 11 |
| Fensel 외 (2020) | KG | 23 |
| Hogan 외 (2021) | KG | 10 |
| Xue·Zou (2023) | KG (품질 관리 서베이) | 17 |
| Wang 외 (2025) | 지리 KG | 23 |

- 가장 많이 인용되는 것은 Wang·Strong(1996)이라고 했다.
- 논문의 지적: "대부분의 저자는 [Wang·Strong과 Zaveri를 빼고] 차원을 어떤 방법으로 정했는지 설명하지 않는다"(3쪽). 즉 **방법론을 밝힌 차원 목록은 Wang·Strong(1996)과 Zaveri 외(2016) 두 편뿐**이라는 것이다.

## 2. 이 논문이 더한 것

LLM과 함께 쓰이면서 새로 중요해졌다고 본 차원을 넣어 24개로 정리했다(표 2).

| 새로 강조한 차원 | 묻는 것 |
|---|---|
| 충실성 | KG의 문장이 붙어 있는 출처로 뒷받침되는가. KG로 만든 답변이 찾아온 문장에 근거하는가 |
| 추적 가능성 | 문장 단위로 출처를 확인할 수 있는가 |
| 맥락 유효성 | 그 문장이 성립하는 조건(시간, 장소, 상황)을 나타내는가 |
| 비용 효율 | 추론 비용 등 |
| 근거 효과 | KG가 그것을 쓰는 모델의 정답률을 얼마나 올리고 환각을 얼마나 줄이는가 |
| 구조 충실도 | KG가 분야의 개념 구조를 보존하는가 |

지표는 "계산할 수 있는 것"과 "사람의 판단이 필요한 것"으로 나눴다.

## 3. 평가 절차 네 단계

1. 확인: 사용자, 쓰임, 평가할 KG를 정한다.
2. 설정: 차원과 지표마다 중요도 가중치를 준다.
3. 평가: 지표 점수를 가중합해 차원 점수를, 차원 점수를 가중합해 KG 총점을 낸다.
4. 활용: 가중치를 조정하고 KG끼리 비교한다.

요점은 **쓰임에 따라 볼 차원을 고른다**는 것이다. 논문도 "제안한 차원과 지표는 우리의 해석이고 쓰임에 맞춰 조정하라는 것"이라고 했다(7쪽).

# 2부. Kommineni 외 (2024): CQ에서 KG까지, 그리고 평가

## 0. 먼저 알아 둘 것

- **논문.** Kommineni, V. K., König-Ries, B., & Samuel, S. (2024). From human experts to machines: An LLM supported approach to ontology and knowledge graph construction. arXiv:2403.08345v1 (2024년 3월). 10쪽.
- 1번 논문(Al Mustafa·König-Ries, 2026)과 같은 연구실(예나 대학 König-Ries)이다.
- 규모가 작다. 논문 5편으로 시험한 것이다.

## 1. 파이프라인

| 단계 | 한 일 | 사람 |
|---|---|---|
| 1. 자료 | 딥러닝을 쓴 생물다양성 논문 61편 중 5편 | |
| 2. CQ 생성 | ChatGPT로 CQ 생성 → 도메인 전문가 2명이 고치고 추가. 40개 | **참여** |
| 3. 온톨로지 | LLM이 CQ에서 개념과 관계를 뽑아 온톨로지 생성. 클래스 45, 관계 41 | |
| 4. CQ 답변 | 논문마다 RAG로 CQ 40개의 답을 생성 | |
| 5. KG 구축 | CQ 답변과 온톨로지를 LLM에 주어 KG 생성 | |
| 6. 평가 | 판정 LLM이 사람이 단 정답에 비추어 채점 | **참여** |

우리와 순서가 같다(CQ → 온톨로지 → KG → 평가). 다른 점은 KG를 **CQ의 답변에서** 만든다는 것이다. 우리는 원본 자료에서 만든다.

## 2. 평가를 어떻게 했나

**① CQ 답변 평가**

- 전문가 한 명이 논문 5편에 대해 CQ별 정답 글을 달고, 생성된 답 200개(5편 × 40개)를 맞음·부분·틀림으로 판정했다.
- 판정 LLM이 정답과 생성 답의 일치를 0~10점으로 매겼다. 6점 이상은 맞음, 3점 미만은 틀림, 나머지는 부분.
- **사람과 판정 LLM이 200개 중 42개에서 달랐다.** 대부분 사람이 "부분"이라고 한 것을 LLM이 "틀림"으로 본 경우였다.

**② KG 평가**

- 판정 LLM이 KG의 개체가 해당 CQ 답변에 나오는지를 확인했다.
- 가장 좋은 조합에서 개체 203개 중 142개가 CQ 답변과 맞았다. 논문별로는 24%에서 92%까지 차이가 컸다. 의미 있는 KG가 만들어지지 않은 조합도 있었다.

## 3. 저자들이 밝힌 한계와 결론

- 만들어진 KG의 일관성이 들쭉날쭉하다. 정보를 못 찾으면 "명시되지 않음"이라고 넣기도 하고 개체를 빼기도 한다.
- 같은 클래스에 같은 값을 가진 개체가 여러 개 생긴다.
- 프롬프트를 조금만 바꿔도 결과가 달라진다.
- 결론: LLM이 사람의 수고를 줄일 수 있지만 **"자동으로 만든 KG의 평가에는 사람이 참여하는 방식을 권한다"**(초록).

# 5. 우리 연구에 주는 것 (내 정리)

## Huaman (2026)에서

| 가져올 것 | 내용 |
|---|---|
| 차원의 계보 | 품질 차원은 Wang·Strong(1996) → Zaveri(2016) → KG 문헌으로 이어진다. 방법을 밝힌 것은 앞의 둘뿐이다. 우리가 Zaveri를 기준으로 삼는 것이 타당하다는 근거가 된다 |
| 쓰임에 따라 고른다 | 24개를 다 볼 필요가 없다. 우리 쓰임(운영자의 질문에 근거를 붙여 답하기)에 맞는 것만 고르면 된다 |
| 우리가 이미 갖춘 차원 | 추적 가능성과 충실성. 우리 KG는 모든 Entity에 근거가 연결되어 있고(규칙 검사 통과), 답변에 출처 번호가 붙는다. 이것이 최신 문헌이 새로 강조하는 차원이다 |
| 맥락 유효성 | 운영기준에 "언제부터 적용되는가"가 붙어 있는가. 우리는 별표 3의 연혁을 근거로 가지고 있다 |

**주의.** 개념 틀이라 적용 결과가 없다. "이 틀로 평가했다"가 아니라 "차원을 고르는 데 참고했다"고 말해야 한다.

## Kommineni 외 (2024)에서

| 가져올 것 | 내용 |
|---|---|
| 같은 순서의 선례 | CQ → 온톨로지 → KG → 평가. 우리 파이프라인의 순서가 혼자만의 것이 아니다 |
| CQ를 전문가가 검토 | LLM이 만든 CQ를 전문가 2명이 고쳤다. 11/13에 정리한 "CQ를 LLM으로 만들고 사람이 추린다"와 같은 방식 |
| LLM 판정의 한계 수치 | 사람과 판정 LLM이 200개 중 42개(21%)에서 달랐다. 운영행위 68개를 LLM에게 판정시키는 방안의 위험을 보여 준다 |
| 사람 참여 권고 | 자동으로 만든 KG의 평가에는 사람이 필요하다는 결론 |

**순환 문제에 대해.** 이 논문은 CQ로 온톨로지를 만들고, CQ의 답변으로 KG를 만들고, 같은 CQ의 답변으로 평가한다. 순환을 따로 다루지 않았다. 다만 평가의 기준은 CQ가 아니라 **사람이 따로 단 정답**이다. 순환을 끊는 것은 CQ를 나누는 것만이 아니라 **기준을 바깥에서 가져오는 것**으로도 된다는 점을 보여 준다. 우리의 경우 바깥 기준은 원본 자료와 사람 판정이다.

**우리와 다른 점.** 이 논문의 KG 평가는 "KG의 개체가 CQ 답변에 나오는가"다. KG가 CQ 답변에서 만들어졌으니, 옮기는 과정만 확인한 것이다. 답변 자체가 맞는지는 ①에서 따로 봤다. 두 단계로 나눠 본다는 점은 우리 구조(원본 대조와 사람 판정)와 닮았다.

## 6. 세 편을 합쳐 보면

| | Al Mustafa 2026 | Huaman 2026 | Kommineni 2024 |
|---|---|---|---|
| 준 것 | 표에서 만든 KG의 평가 단계 셋과 지표 | 품질 차원의 계보와 고르는 절차 | CQ에서 KG까지의 선례와 LLM 판정의 한계 |
| 적용 결과 | 없음 (결과 장이 비어 있음) | 없음 (개념 틀) | 있음 (논문 5편, 작은 규모) |
| 심사 | 심사 전 원고 | 확인 안 됨 | arXiv 원고 |

세 편 모두 "틀은 있으나 큰 규모의 적용 결과는 없다"는 상태다. **KG 검증에 정해진 표준 절차가 아직 없다**는 것이 최신 문헌에서도 확인된다. Hofer 외(2024)가 "전체 파이프라인을 평가하는 표준은 없다"고 한 것과 같다. 그래서 우리가 문헌의 차원과 전략을 골라 우리 KG에 맞는 절차를 직접 짜는 것은 예외적인 일이 아니다.
