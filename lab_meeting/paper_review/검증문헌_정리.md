# 검증 문헌 정리 (2026-11-12 기준)

지금까지 모은 검증 관련 문헌 23편을 한곳에 정리했다. 랩미팅 자료가 아니라, 어떤 검증 방법을 골라 적용할지 정하기 위한 작업용 정리다.
원문 PDF는 `references/evidence_literature/`와 그 아래 `validation/`에, 해당 부분의 해석은 `검증부분_해석*.md`에 있다.

정리 기준은 문헌마다 네 가지다.
- 검증 대상: 온톨로지, KG(채운 값), 지식 추출, 답변 중 무엇을 검증했나
- 검증 방법: 무엇을 했나
- 판정 기준: 무엇에 비추어 맞고 틀림을 정했나
- 한계: 저자가 밝힌 한계 또는 원문에서 확인되는 한계

## 1. 구축 연구가 실제로 한 검증

온톨로지나 KG를 직접 만든 연구가 자기 결과물을 어떻게 검증했는지다.

| 연구 | 분야 | 검증 대상 | 검증 방법 | 판정 기준 | 한계 |
|---|---|---|---|---|---|
| OntoDSMS (Zhou 외, 2023) | 댐 안전 모니터링 | 온톨로지를 쓴 시스템 | 콘크리트댐 하나(12구간, 센서 179개)에 적용. 질의 예시 5개를 실행하고 같은 내용의 SQL 질의 결과와 대조. 개체 수와 검색 시간(10회 평균) 비교 | 원래 데이터베이스 | 질의는 다 만든 뒤 고른 예시. 검증 방법 문헌 인용 없음 |
| DDKG (Huang 외, 2026) | 댐 결함 | 지식 추출(LLM의 분류) | 전문가가 검증한 표본 1,200개로 정밀도·재현율·F1 측정. 구성요소를 하나씩 뺀 비교 실험. 분류 결과를 온톨로지 제약으로 거르고, 걸린 것을 전문가가 검토해 온톨로지를 확장. 검색 예시와 지역 분석 사례 | 전문가가 단 정답 | 온톨로지와 KG 자체의 체계적 평가(구조, 완전성, 일관성)는 향후 과제로 남김. 검증 방법 문헌 인용 없음 |
| FloodOntology (Li 외, 2025) | 홍수 위험 소통 | 온톨로지 | ① 구조 지표(OntoQA의 관계 풍부도, 상속 풍부도)를 기존 온톨로지 3개와 비교. ② CQ의 30%를 따로 떼어, 그 CQ의 개념이 온톨로지에 있는지 임베딩 유사도로 확인(개념 포괄도). ③ 구축 중 LLM이 낸 후보를 전문가가 검토(개체 후보 약 8%, 관계 후보 약 10% 거절). ④ 홍수 경보문을 온톨로지로 다시 써서 전후 비교 | 기존 온톨로지, 평가자 3명 다수결, 사례 | 평가가 주로 구조적·정성적. 유사도 기준값이 모호(0.3이면 100%, 0.9이면 7.6%). 과업 중심 정량 평가가 다음 단계라고 밝힘 |
| 홍수·재난 온톨로지 12편 (Li 외 2025의 표 1) | 홍수·재난 | 온톨로지 | 추론기 검사 6편, CQ를 질의로 확인 4편(모두 추론기와 함께), 사례 적용 3편, 구조 지표 1편, 설계 오류 점검 도구 1편, 전문가 인터뷰 1편, 검증 없음 2편 | 논리 규칙, CQ, 사례, 전문가 | 표의 한 칸 요약이라 각 연구의 세부는 확인하지 못함 |
| GraphAide (Purohit 외, 2024) | 일반(KG 질의응답) | 구축 구성요소와 답변 | 구성요소별 RAGAS 지표(답 정확도, 맥락 관련성, 답 관련성, 의미 유사도 등). 증강 수준이 다른 답변의 정성 비교 | 평가용 데이터셋 | 정량적 향상을 보고하는 정식 평가는 향후 작업으로 남김 |

## 2. 온톨로지 검증 방법을 다룬 문헌

### 2.1 CQ로 검증하는 방법

| 문헌 | 내용 | 우리에게 주는 것 |
|---|---|---|
| Noy·McGuinness (2001) | CQ는 나중에 리트머스 시험으로 쓰인다(온톨로지가 이 질문에 답할 만큼 정보를 담았는가). 초기 온톨로지는 응용에 써 보거나 전문가와 논의해 평가한다. 온톨로지의 품질은 설계한 목적의 응용에 써 보아야만 평가할 수 있다 | 9~10월 CQ 검증의 근거. 절차는 없음 |
| Alharbi 외 (2023) | Noy를 인용해 CQ를 "온톨로지 개발과 평가의 리트머스 시험"이라 함. CQ가 검증과 평가를 뒷받침한다며 Bezerra·Freitas, Keet·Ławrynowicz를 인용. CQ는 대부분의 방법론에서 필수지만 공개되지 않는 경우가 많다 | Noy에서 CQ 검증 연구로 이어지는 인용 고리 |
| Bezerra·Freitas (2017) | CQ 하나를 ⟨질의, 기대 답⟩ 쌍의 시험 사례로 정의. 실행 결과가 기대 답과 같으면 통과. 시험 계획, 시험 묶음, 실행 결과(기대 답과 나온 답, 시험한 사람, 날짜)를 정의. Pizza, Travel, Wine 온톨로지로 예비 실험 | 질의 실행 대조의 정의와 기록 방식 |
| Keet·Ławrynowicz (2016) | 시험 주도 개발. 시험을 먼저 만들어 실패를 확인 → 온톨로지 수정 → 같은 시험 통과 확인 → 전체 시험 재실행(회귀 시험). 원문은 8단계 | 구조를 고칠 때의 순서 |
| Lippolis 외 (2025) | CQ 판정을 예/아니오/아니오(경미)로 나눔. LLM이 판정과 질의를 제안하는 도구 실험(지식 엔지니어 19명): 제안이 맞으면 정확도 70.5%→83.2%, 틀리면 71.9%→43.9%. CQ 검증은 수작업이 많고 CQ의 모호함에 좌우된다 | 판정 방식. LLM 보조는 쓰지 않는 근거 |
| Keet·Khan (2024) | CQ를 다섯 종류로 나눔. 범위 설정 CQ는 답할 수 없어도 되지만 검증 CQ는 형식화할 수 있고 반드시 답할 수 있어야 한다. 좋은 CQ의 기준과 지침이 부족하다 | 검증에 쓸 CQ의 조건 |
| Li 외 (2025) | CQ를 70%(구성)와 30%(평가)로 나눔. 평가자 3명 중 2명 이상 승인한 것만 남김 | 구성용과 검증용을 나누는 선례, 다수결 기준 |

미열람: Gruninger·Fox (1995, CQ의 출처), Vrandečić·Gangemi (2006, 단위 시험 제안), Blomqvist 외 (2012, 온톨로지 시험 방법론). 다른 논문의 설명으로만 확인했다.

### 2.2 CQ의 품질과 전문가 참여

| 문헌 | 내용 | 우리에게 주는 것 |
|---|---|---|
| Alharbi 외 (2025) | 같은 요구사항에서 엔지니어, 패턴, LLM으로 CQ를 만들어 비교. 엔지니어가 만든 CQ의 수용률이 90% 이상으로 가장 높음. 질문 단위 겹침: 엔지니어 두 명 사이 15.3%, 두 LLM 사이 2.9%, LLM과 사람 사이 거의 0% | CQ는 만드는 사람에 따라 크게 달라진다 |
| Watkiss-Leek 외 (2026, IDEA2) | 엔지니어는 CQ를 형식화할 줄 알지만 분야 지식이 부족하고, 도메인 전문가는 그 반대다. 전문가가 CQ를 검토하고 고치는 과정을 합의까지 반복해 CQ의 수용도와 관련성을 높임 | 전문가가 CQ를 검토하는 절차의 선례 |

### 2.3 평가 접근 전반

| 문헌 | 내용 | 우리에게 주는 것 |
|---|---|---|
| Wilson 외 (2023) | 2010~2021년 온톨로지 품질 평가 연구 리뷰. 구조와 내용을 들여다보고 "바르게 만들었는가"를 보는 평가와, 쓰는 목적에 맞는지 "맞는 온톨로지를 만들었는가"를 보는 평가를 구분. 뒤의 것은 주로 사용자와 도메인 전문가가 참여. 정확성은 맞게 답한 CQ의 수로, 기능적 완전성은 충분한 답을 낸 CQ의 수로 잰다. 구축 방법론들은 평가 방법을 자세히 설명하지 않는다 | 검증의 두 관점, 결과를 세는 지표 |
| Raad·Cruz (2015) | 평가 접근 네 가지: 기준 온톨로지 비교, 분야 문서 비교, 과업 기반, 품질 기준. 어떤 접근도 모든 기준을 평가하지 못하고, 맞는 접근은 평가 목적에 따라 다르다 | 접근의 분류. 오래된 문헌이라 Wilson 외를 통해 인용 |
| Bandeira 외 (2016, FOCA) | 평가자가 13문항에 답해 점수를 매기는 방법론. "CQ를 정의했는가", "CQ에 답했는가"가 완전성 항목. Gruber의 설계 기준 다섯 가지를 정리 | Gruber 기준의 출처 |
| Li·Garijo·Poveda-Villalón (2026) | 온톨로지 공학에 LLM을 쓴 연구 리뷰. 구현 단계의 평가를 "온톨로지를 CQ와 분야의 요구에 비추어 검증하는 것"으로 정의 | 평가 활동의 정의 |

## 3. KG(채운 값) 검증 방법을 다룬 문헌

| 문헌 | 내용 | 우리에게 주는 것 |
|---|---|---|
| Zaveri 외 (2016) | 품질 차원 18개, 지표 69개. 사용 맥락과 무관한 차원 다섯 가지: 구문 유효성, 의미 정확성(값이 현실의 사실과 맞는가), 일관성(모순이 없는가), 간결성, 완전성 | KG 검증에서 볼 차원 |
| Paulheim (2017) | 평가 전략 세 가지: 그래프 일부에 사람이 정답을 다는 부분 정답, 외부 KG나 데이터베이스를 정답으로 쓰기, 결과를 사람 판정자에게 주어 맞음·틀림을 표시하는 회고 평가(보통 표본으로, 판정자 간 일치도 보고). 구조(T-box)와 값(A-box)을 구분 | 값 검증의 전략 |
| Gao 외 (2019) | KG 정확도를 "맞는 트리플의 비율"로 정의하고 표본으로 추정. 같은 대상의 트리플을 묶어 확인하면 비용이 준다 | 표본으로 정확도를 추정하는 방법 |
| Abu-Salih (2021) | 도메인 KG는 완전한 참조가 없어 사례 연구와 전문가 평가에 기댄다 | 도메인 KG 검증의 일반적 상황 |

## 4. KG를 쓴 질의응답의 평가를 다룬 문헌

| 문헌 | 내용 | 우리에게 주는 것 |
|---|---|---|
| Draetta 외 (2025, GRADES) | 파이프라인의 단계(정보 추출, 엔티티 연결, 문장화)마다 자동 평가와 사람 평가를 함께 넣는 틀. 최종 답은 도메인 전문가가 평가. 최종 출력만 평가하면 부족하다 | 단계별 평가의 근거 |
| Nuñez 외 (2026, HERMES) | 답변을 낱개 주장으로 나눠, 각 주장이 검색된 그래프 트리플로 뒷받침되는지 판정하는 지표(Grounding Fidelity). CQ 10개, 그래프 6개, LLM 4개로 평가 | 답변이 KG 근거를 따르는지 재는 방법 |

## 5. 문헌에 나온 검증 방법 목록 (고를 후보)

문헌 전체에서 방법만 추려, 검증 대상별로 모았다. 전부 섞어 쓰자는 것이 아니라 이 중에서 고르기 위한 목록이다.

### 온톨로지(구조)

| 방법 | 판정 기준 | 필요한 것 | 우리 상황 |
|---|---|---|---|
| CQ 시험(질의 + 기대 답) | 미리 정한 기대 답 | CQ, 기대 답, 질의 | 가능. CQ와 질의 템플릿이 있고 기대 답은 원자료에서 정할 수 있음 |
| CQ 개념 포괄도 | 임베딩 유사도 기준값 | CQ, 임베딩 모델 | 가능하지만 기준값이 모호하고 정확성을 보지 못함 |
| 추론기 검사 | 논리 규칙 | OWL로 적은 온톨로지 | 지금은 불가(Neo4j 그래프 구조) |
| 구조 지표(OntoQA) | 다른 온톨로지와의 비교 | 비교할 온톨로지 | 비교할 댐 운영 온톨로지가 없음 |
| 사례 적용 | 사례에서의 작동 | 실제 사례 | 가능. 다만 정성적 |
| 전문가 검토 | 전문가의 판단 | 검토자, 절차 | 검토자 섭외 필요 |
| 기준 온톨로지·문서 비교 | 참조 온톨로지, 분야 문서 | 참조 자원 | 참조 온톨로지 없음. 규정 문서는 있음 |

### KG(채운 값)

| 방법 | 판정 기준 | 필요한 것 | 우리 상황 |
|---|---|---|---|
| 제약 검사(허용 관계, 필수 속성, 값 형식) | 온톨로지가 정한 규칙 | 규칙 | 10월에 수행함(구조 검사) |
| 원자료 대조(외부 데이터베이스를 정답으로) | 원자료 | 원자료와 KG의 대응 | 가능. KG가 원자료에서 만들어져 대조할 수 있음 |
| 표본 정확도(표본을 사람이 판정) | 사람의 판정 | 표본 설계, 판정자 | 가능. 판정자 필요 |

### 답변

| 방법 | 판정 기준 | 필요한 것 | 우리 상황 |
|---|---|---|---|
| 단계별 평가(GRADES) | 단계마다 자동 지표와 사람 평가 | 단계별 정답 | 연구 범위를 정한 뒤 검토 |
| 근거 충실도(HERMES) | 검색된 트리플 | 답변, 검색 결과 | 연구 범위를 정한 뒤 검토 |
| RAGAS 지표(GraphAide) | 평가용 데이터셋 | 질문·정답 세트 | 연구 범위를 정한 뒤 검토 |
