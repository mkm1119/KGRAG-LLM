5근거 개체와 출처 기록데이터 구조에 맞춘 응용 · 원본이 DB가 아닌 파일이라 값을 옮겨 오므로, 원본 행으로 되돌아갈 길을 남긴다
(가) 근거 개체: 이 승인이 어느 자료의 어느 행에서 왔는지를 그래프 안의 개체로 둔다
EVI:AP:504, sourceTitle,   환경부 한강홍수통제소 홍수예보 댐방류승인
EVI:AP:504, sourceType,    승인자료
EVI:AP:504, sourceLocator, 순차번호 504
APR:504 —supportedBy→ EVI:AP:504
두 ID가 같은 행에서 나왔으므로 다른 표를 찾지 않고 바로 잇는다.
(나) 출처 기록: 개체마다 원본 파일, 위치, 적용 규칙, 값의 성격을 남긴다
item           = APR:504
source_file    = approval_records_clean.csv
source_locator = row_number_in_file=504
rule           = MR-APR
data_origin    = real
note           = 승인일은 날짜만 있음
· row_number_in_file: 원본 CSV(cp949)의 행 번호 → 원 파일의 504번째 행을 바로 연다.
· rule: 어떤 매핑 규칙으로 만들었는지 (매핑 파일 대신 규칙 ID로 남김).
· data_origin = real: 원본 값을 그대로 옮긴 것 (가공·추정 아님).
응용한 이유 · D2RQ는 가상 그래프라서 질의할 때마다 원본 DB를 직접 읽는다. 그래서 출처를 따로 기록할 필요가 없다. 우리는 CSV 값을 복사해 Neo4j에 저장하므로, 이 기록이 KG 값과 원본 행을 잇는 유일한 연결이다.
6결과물: 504행 하나에서 만들어진 그래프 조각실선 = 이 단계에서 생성 · 점선 = 이후 단계에서 연결
80행 전체에 적용한 결과: Approval 80개 + EvidenceSource 80개, 속성 400개(승인 160 + 근거 240), supportedBy 관계 80개, 출처 기록 160개. 댐 목록(DAM 4개)도 같은 원칙으로 만들었다 (DAM_CD → DAM:1003110, 댐명·댐 유형 → 속성).
