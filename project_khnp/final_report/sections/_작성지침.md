# 최종보고서 절 작성 지침

## 재료 (이것만 쓴다)
- 비교표 행: /home/user/KGRAG-LLM/references/case_survey/tables/<묶음>.json
- 논문별 사실 정리: /home/user/KGRAG-LLM/references/case_survey/facts/<id>.json (수치의 원문 구절은 quotes에 있음)
- 필요하면 논문 원문 글: /home/user/KGRAG-LLM/references/case_survey/txt/<id>.txt 또는 txt_add/<id>.txt
- 8월 공정보고(이 절의 바탕이 된 기존 보고 내용): /home/user/KGRAG-LLM/project_khnp/final_report/src/공정보고_8월.txt

## 반드시 지킬 것
1. 재료에 없는 사실, 수치, 평가를 쓰지 않는다. 재료에서 "본문에 없음"·"-"인 것은 쓰지 않거나 "논문에 제시되지 않음"으로 쓴다.
2. 수치는 사실 정리의 results·quotes에 있는 것만 쓴다. 논문 안에서 수치가 어긋난다고 사실 정리에 적힌 경우 표의 값을 쓰고 어긋남을 한 번 밝힌다.
3. 편수를 셀 때는 비교표의 tags를 실제로 세어서 쓴다(직접 세고, 어림하지 않는다).
4. 주관적 수식어를 쓰지 않는다(예: 매우, 뛰어난, 획기적, 효과적으로, 성공적으로). "테스트", "실험해 보았다" 같은 표현 대신 조사·검토·비교·정리로 쓴다. 본 과업이 한 일은 문헌 조사와 검토다.
5. 이전 문서를 가리키는 말(공정보고에서, 앞서 보고한 등)을 쓰지 않는다.
6. 논문을 가리킬 때는 "저자(연도) ⟦문헌:id⟧" 형식으로 쓴다. id는 사실 정리 파일 이름(.json 제외). 예: Yang 외(2024) ⟦문헌:07_수리시설점검QA⟧. 저자·연도 표기는 비교표의 source를 따른다.
7. 표와 그림을 본문에서 가리킬 때는 ⟦표:라벨⟧, ⟦그림:라벨⟧로 쓴다(번호는 나중에 매긴다). 캡션에는 번호를 쓰지 않는다.
8. 용어: 지식그래프는 처음 한 번 "지식그래프(KG)"로 쓰고 이후 "KG". 온톨로지, Class, 관계는 그대로. "정형 자료/비정형 자료(문서 자료)". 모델·데이터셋·지표 이름은 원문 표기.

## 문체
- 소절 첫머리와 각 "가.~마." 첫머리의 설명 문단(BODY)은 "~하였다/~이다"로 끝나는 서술문.
- 그 아래 내용은 개조식 3단계: SQ(□ 큰 항목, 명사구) → CI(◦ 설명, 명사형 종결: "~을 정리", "~으로 구성", "~임") → DS(- 세부, 명사형 종결).
- 한 항목은 한 문장. 한 문장이 80자를 넘으면 나눈다.

## 소절의 구성 (교수 지도 사항: 조사 → 분류 → 굵직한 비교 → 추린 사례의 상세 비교 → 판단)
- 가. 조사 대상: 조사 범위와 사례 목록. 표 1개(번호, 사례, 출처, 게재처 유형, 대상 분야).
- 나. 사례의 분류: 분류 기준(2~3개 축)과 기준별 편수. 표 1개(분류 기준별 편수와 해당 사례).
- 다. 주요 항목 비교: 모든 사례를 같은 항목으로 비교. 표 2개로 나눈다 — ① 자료·구조·지식 구조·검색, ② 생성 모델·미세조정·운영 환경·평가 방법·대표 결과. 표 뒤에 항목별로 확인된 경향을 편수와 함께 서술.
- 라. 주요 사례 상세 비교: 댐 운영 질의응답과 가까운 사례 3편을 고르고(고른 기준을 밝힘), 사례마다 (1)(2)(3) 소제목 아래 풀려는 문제, 자료, 처리 단계, 평가와 결과, 한계를 서술. 사례마다 구조도 자리 1개(FIGPLACE). 끝에 세 사례를 나란히 놓은 비교표 1개.
- 마. 검토 결과: 위 비교에서 확인된 사실을 근거로, 댐 운영 의사결정 지원에 적용할 때 적절한 방식과 고려사항을 정리. 근거가 된 사례를 ⟦문헌:id⟧로 밝힌다.

분량: 표를 뺀 본문 글자 수 10,000~13,000자. 실험이 없는 논문(전망·요구사항·비용 분석)은 성능 비교에 넣지 않고 "가"나 "다"에서 따로 다룬다.

## 출력 형식
파일: /home/user/KGRAG-LLM/project_khnp/final_report/sections/<소절 파일 이름>.json — 아래 항목의 배열(UTF-8, 유효한 JSON)

```json
[
 ["H3", "1.1.2 RAG 기반 질의응답 사례"],
 ["BODY", "서술문 문단."],
 ["H4", "가. 조사 대상"],
 ["H5", "(1) 소제목"],
 ["SQ", "큰 항목"],
 ["CI", "설명"],
 ["DS", "세부"],
 ["TABLE", {"label": "rag_list", "caption": "RAG 기반 질의응답 사례 목록", "widths": [6, 22, 22, 14, 36], "align": ["c","l","l","c","l"], "rows": [["번호","사례","출처","게재처 유형","대상 분야"], ["1","...","...","...","..."]], "note": "주: ... (없으면 생략)"}],
 ["FIGPLACE", {"label": "rag_fig1", "caption": "○○ 시스템의 구조", "source": "Yang 외(2024)의 Fig. 2를 재구성하여 삽입"}]
]
```
- H3는 소절 제목 한 번만. SQ/CI/DS 글에는 □ ◦ - 기호를 붙이지 않는다(자동으로 붙는다).
- 표의 칸 글은 짧게(칸마다 45자 이내 권장). 표 한 개는 25행 이내, 넘으면 나눈다. 출처 칸에는 "저자(연도) ⟦문헌:id⟧"를 쓴다.
- FIGPLACE의 source에는 그 논문의 key_figures에 있는 그림 번호를 쓴다.

끝나면 JSON이 파싱되는지 확인하고, 본문 글자 수(표 제외), 표 수, 고른 3개 사례와 이유, 재료가 부족해 쓰지 못한 부분을 보고한다.
