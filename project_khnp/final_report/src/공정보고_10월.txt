□ 용역 사업배경 및 목적
◦ (추진배경) 댐 운영은 수문 데이터뿐만 아니라 과거 운영경험, 매뉴얼, 관련 법령 등 비정형 데이터에 대한 종합적 판단이 필수적이나, 이를 정형화해 의사결정에 연결하는 모델/시스템이 부재함
◦ sLLM 기반 스마트 의사결정 체계를 통해 비숙련 운영자를 보조하고, 방류 시점을 정밀 제어하는 수력발전 운영 효율화 기술에 대한 수요가 높음
◦ (목적) sLLM 기반 댐 운영 의사결정 및 발전 최적화 프레임워크 구축을 위한 기술적 타당성 검토

◦ 국내 운영 여건 조사 : 국내 댐 운영 현장의 업무 절차, 자료 활용 방식, 의사결정 구조, 시스템 운영 환경에 대한 현장 방문 조사를 통해 기술 적용 시 고려사항을 도출
◦ 적용 기술요소 및 모델 제안 : 지식기반 구성, 수문자료 연계, 운영자 지원체계 등 핵심 기술요소를 도출하고, 이를 구현할 sLLM 모델 및 RAG 아키텍처(안)를 제안

□ sLLM 후보군 평가 방향
◦ 후보 모델 조사 : Llama 3·Mistral·Qwen 계열 7~14B급 오픈소스 dense 모델을 온프레미스 배치 가능성·미세조정 효율 기준으로 조사·비교
◦ 모델 구조 및 특성 검토 : GQA, RoPE, SwiGLU, RMSNorm 등 아키텍처 요소와 장문 처리·한국어 대응·수치문서 해석 특성을 검토하여 댐 운영 분야 적용성을 분석
◦ 후보군 적용방안 제시 : 장문 운영매뉴얼·규정문서 처리, 수치-텍스트 복합 해석, RAG 결합 시 근거 기반 응답 일관성 등을 중심으로 후보군을 비교하여 적합한 sLLM 및 적용방안(안) 제시
□ 도메인 특화 성능 향상 전략

◦ 경량 미세조정 방식 검토 : 전체 파라미터 재학습(full fine-tuning) 대비 제한된 도메인 데이터·온프레미스 자원 환경에 적합한 PEFT(LoRA·QLoRA·DoRA) 중심 성능 향상 방안 검토
◦ 성능 향상 전략 제시 : 검색·프롬프트 구성·응답 생성 모듈을 연계한 구조와 검증 모듈·경량 앙상블 결합 방식을 검토하여 근거 기반 응답 정확도·의사결정 신뢰성을 높이는 전략(안) 제시

□ 검토 방법
◦ 본 과업의 RAG-LLM 프레임워크를 온톨로지 설계, 자료 구조화·매핑, 수치자료 연계·저장, 질의 해석·검색, 근거 구성·응답의 5개 파트로 구분하고, 파트마다 선행연구의 기술과 방법을 분석하여 적용할 기술과 후속 검토 사항을 정리
◦ 분석 대상: 온톨로지 설계 방법론 [1][6], 댐 분야 온톨로지·KG 구축 사례 [2][3], 그래프 기반 질의응답 시스템 [4][5], 검색 결합 생성(RAG) [7], 그래프 데이터베이스 [8]
□ RAG-sLLM 아키텍처(안) 구성 계층
◦ 선행연구 분석 결과를 바탕으로 지식기반, 검색, 응답의 3개 계층으로 아키텍처(안) 구성 (그림 1, 표 1)
- 지식기반 계층: 온톨로지 기반 KG에 개체 간 관계와 근거 출처를 구조화하고, 수치 시계열과 규정 원문은 외부 저장소에 두어 KG와 키로 연계 [2][3]
- 검색 계층: 질의에서 의도와 대상을 파악하고, 의도에 따라 KG와 외부 저장소에서 근거를 검색하여 출처가 붙은 근거로 구성 [4][5]
- 응답 계층: 구성된 근거를 입력으로 sLLM이 근거 중심으로 응답하며, 모델 및 성능 향상 방안은 3, 4에서 제시
◦ 계층 사이에서는 질의 → 의도·대상 → 근거 → 근거 묶음 → 응답의 순서로 정보가 전달되며, 지식기반 계층은 데이터 파이프라인(2.3)의 결과로 구성

그림 1 RAG-sLLM 아키텍처(안) 구성 계층
□ 파트별 기술 분석 및 적용 방향
◦ ① 온톨로지 설계 — 선행연구 기술 분석 (표 2)
- 단계적 설계 방법론 [1]: 도메인·범위 결정 → 기존 온톨로지 재사용 검토 → 용어 나열 → 클래스·계층 정의 → 속성 정의 → 제약 정의 → 인스턴스 생성의 7단계이며, 하나의 정답이 있는 것이 아니라 반복적으로 개선하는 과정으로 제시
- 질문 기반 범위 설정 [1]: 온톨로지가 답해야 할 질문(Competency Question)을 범위 설정과 점검에 활용하되 모든 질문을 망라할 필요는 없다고 설명
- 초기 온톨로지와 확장 [6]: 전문가가 초기 온톨로지와 최상위 클래스를 정의하고, 질문 생성과 권위 문서를 통해 확장 후보를 만든 뒤 임베딩 유사도 필터와 전문가 검토를 거쳐 반영
- 댐 분야 적용 [2][3]: 댐 안전 모니터링에서 [1]의 절차를 적용하고 [2], 모든 최상위 클래스를 댐 개체에 연결하는 구조로 다원 자료를 하나의 KG에 정리 [3]
◦ ① 온톨로지 설계 — 적용 방향
- 질문 기반으로 필요한 Class·관계·속성을 정의한 초기 온톨로지를 두고 KG 구축·검증 결과로 보완하는 반복 절차와 댐 중심 연결 구조 채택 [1][3][6]
- LLM을 이용한 질문 생성과 자동 확장 후보 필터는 자료 범위와 검증 체계가 정해진 뒤 검토
◦ ② 자료 구조화·매핑 — 선행연구 기술 분석 (표 3)
- 구조화 자료 대응 [2]: 관계형 DB를 가상 RDF 그래프로 접근하여 데이터를 복제하지 않고 조회하며, 테이블은 클래스에, 컬럼은 속성에, 행은 인스턴스에, 셀 값은 리터럴에 대응시키고 자동 생성된 매핑은 온톨로지 용어에 맞게 수정
- 문서 자료 구조화 [3]: 자료를 구조화 표와 비정형 텍스트로 나누고, 텍스트는 변환·OCR·정규식으로 블록을 분리한 뒤 규칙 기반 추출 또는 LLM 기반 분류(미세조정, 온도 변화를 준 반복 추론의 투표, 온톨로지 제약 일관성 검사)로 처리
- LLM 기반 지식 추출 [4][5]: 온톨로지로 LLM 응답 형식을 제한하고 개체 중의성 해소와 스키마 검증으로 일관성을 확보 [4], 개체·관계를 동시에 추출하고 F1로 성능을 평가 [5]
◦ ② 자료 구조화·매핑 — 적용 방향
- 정형 자료는 열을 속성에, 행을 개체에 대응시키고 값은 원본 유지 [2]
- 문서 자료는 구조가 일정한 경우 규칙 기반 추출을 적용 [3]
- 관계는 자료에서 근거가 확인된 개체 쌍에만 생성 [6]
- LLM 기반 추출은 정확도를 검증할 기준이 마련된 뒤 검토 [3][4][5]
◦ ③ 수치자료 연계·저장 — 선행연구 기술 분석
- 가상 매핑 [2]: 수치 데이터를 원본 DB에 두고 온톨로지 질의로 조회하여 복제 없이 접근
- 외부 함수·저장소 연계 [4]: 시계열 등 외부 자료를 불러오는 외부 함수 실행 기능을 시스템 기능으로 제시 (보고된 실험에서는 다루지 않음)
- 그래프 데이터베이스 저장 [3][8]: 추출 결과를 JSON으로 통합하고 스크립트로 Cypher 명령문을 생성하여 Neo4j에 일괄 적재하며, 그래프 데이터베이스는 개체를 노드, 관계를 간선으로 저장
◦ ③ 수치자료 연계·저장 — 적용 방향
- KG에는 개체·관계와 찾아가는 식별 키만 저장하고 수치 시계열과 규정 원문은 외부 저장소(측정자료, 문서)에 보관 [2][4], KG는 Neo4j에 저장하고 Cypher로 조회 [3][8]
◦ ④ 질의 해석·검색 — 선행연구 기술 분석 (표 4)
- 의도 파악 [5]: 질문의 의도를 규칙 기반, 지도학습 기반, LLM 기반 결과를 F1 점수 비중으로 투표하여 정하며, LLM 출력의 안정성이 충분하지 않다고 서술
- 질의 규칙 [5]: 의도 범주마다 자연어 질문을 Cypher 질의로 바꾸는 규칙을 미리 설계하고, 조회한 KG 지식을 LLM 프롬프트에 포함하여 우선 사용하도록 함
- 하이브리드 검색 [4]: 벡터 검색과 서브그래프 매칭을 결합한 컨텍스트 생성, 질의 확장, Cypher 자동 생성
◦ ④ 질의 해석·검색 — 적용 방향 (KG 조회 단계)
- 정해진 의도 범주를 두고 질문에서 의도와 대상을 추출한 뒤, 의도별 질의 규칙(Cypher)으로 KG를 조회 [5]
- 추출된 의도와 대상이 허용 범위 안에 있는지 확인한 뒤 조회
◦ ④ 질의 해석·검색 — 검토 방향 (LLM 연계 단계)
- 의도 파악에 LLM을 사용할지, 규칙·학습 기반과 투표로 결합할지는 LLM 출력의 안정성 한계 [5]를 고려하여 sLLM 후보군 평가(3)와 성능 향상 전략(4)의 결과에 따라 결정
- 벡터 검색 결합 [4] 여부도 같은 방식으로 확정
◦ ⑤ 근거 구성·응답 — 선행연구 기술 분석
- 검색 결합 생성 [7]: 검색한 근거를 생성 모델의 입력에 결합하여 모델 내부 지식에만 의존하지 않고 응답
- 지식 활용 프롬프트 [5]: KG에서 얻은 지식을 프롬프트에 포함하고 LLM이 이를 우선 사용하도록 하여 응답의 근거를 확보
- 컨텍스트 생성과 평가 [4]: 검색 결과를 컨텍스트로 구성하고, 여러 구성요소로 이루어진 시스템은 단일 지표만으로 평가하기 어려워 구성요소별 지표가 필요하다고 설명
◦ ⑤ 근거 구성·응답 — 적용 방향 (근거 구성 단계)
- KG와 외부 저장소에서 검색한 결과를 출처가 붙은 근거로 구성하여 응답 모델의 입력에 결합하는 구조 채택 [5][7]
- 검색(근거 확보)과 응답(근거 기반 답변)을 구분하여 평가를 설계 [4]
◦ ⑤ 근거 구성·응답 — 검토 방향 (LLM 연계 단계)
- 프롬프트 프레임의 세부 항목(근거 사용 원칙, 답변 표기 방식)은 sLLM 후보군 평가(3)와 성능 향상 전략(4)의 결과를 반영하여 확정

□ 데이터 파이프라인 구성
◦ 1.3의 지식기반 계층을 구성하는 데이터 파이프라인을 수집 → 전처리 → 지식기반 구성의 3단계로 설계하고, 현장방문으로 확보할 한수원 내부 자료를 수집 단계에 추가 (그림 2, 표 7)
- 수집: 필요한 공개자료와 한수원 내부 자료를 자료별 제공 방식, 단위·주기에 맞춰 수집

- 지식기반 구성: 온톨로지에 맞춰 개체·관계를 생성하고 검증한 뒤 KG와 외부 저장소에 저장

그림 2 데이터 파이프라인(안): 수집, 전처리, 지식기반 구성
□ 수집 단계(안)
◦ 수집 대상은 9월에 조사한 공개자료 중 필요한 자료를 기준으로 하되, 한수원 내부 자료의 구성이 확정되지 않았으므로 자료 구성은 현장방문 결과에 따라 확정
- 자료별 제공기관, 제공 방식, 단위·주기를 기준으로 수집경로 정리 (9월 조사 결과)
- 수치 시계열은 식별 키(대상 코드, 시점)를 기준으로 수집하여 외부 저장소에 보관
- 문서 자료(규정 등)는 문서 단위로 수집하여 문서 저장소에 보관
- 한수원 내부 자료는 현장방문에서 보유 현황과 접근 경로를 확인한 뒤 수집경로에 추가
□ 전처리 단계(안)
◦ 자료 유형(구조화 자료, 문서 자료)에 따라 처리 경로를 구분하고 공통 정리 항목을 적용 (그림 3, 표 6)
- 구조화 자료: 열은 속성에, 행은 개체에 대응시키고 값은 원본 그대로 유지하며 식별 키로 연결 [2]
- 문서 자료: 문서 단위로 분리하고, 구조가 일정한 경우 규칙 기반으로 값을 추출 [3]
- 공통 정리: 표기 형식을 통일하고 자료의 출처와 시점 정보를 유지하며, 원본은 변경하지 않고 정리 내용을 기록으로 남겨 추적
- 구조화·문서 자료의 구체적인 구성은 한수원 자료 확인 후 확정

□ 지식기반 구성 단계(안)
◦ 온톨로지에 맞춰 개체를 만들고 관계를 연결한 뒤 검증하여 저장
- 개체 생성: 전처리된 자료를 온톨로지의 Class와 속성에 맞춰 개체로 생성하고 개체마다 근거 출처를 연결
- 관계 연결: 자료에 적힌 값(식별 키)이 일치하는 개체 쌍에만 관계를 생성하고 근거 없는 추정 연결은 만들지 않음 [6]
- 검증: 온톨로지가 허용한 관계의 양 끝 Class, 필수 속성, 값 형식, 근거 연결 여부를 점검하고, 질문마다 정해진 경로로 필요한 개체에 도달하는지 확인 [3]
- 저장: 개체·관계는 JSON으로 정리하여 Cypher 명령문으로 변환해 Neo4j에 적재하고, 수치와 원문은 외부 저장소에 둠 [3]
□ 온톨로지 설계방안
◦ 온톨로지는 질문에서 출발하여 초기 온톨로지를 정의하고, KG 구축과 검증 결과로 보완하는 절차로 설계 (그림 4)
- 질문(CQ)과 범위를 정한 뒤 이에 답하는 데 필요한 Class·관계·속성을 온톨로지로 정의
- 구축한 KG로 질문에 필요한 개체에 도달하는지 점검하고, 도달하지 못하면 부족한 관계나 속성을 온톨로지에 추가
- 보완 내용은 전문가 검토를 거쳐 반영하며 자동 생성된 내용은 그대로 수용하지 않음 [1][6]

◦ 9월 조사·검토 결과를 바탕으로 수집경로, 온톨로지 설계방안, 데이터 전처리 체계(안)를 3단계의 입력·처리·산출로 정리 (표 7)

- 온톨로지 설계방안: 식별 키 기준 연결, 출처·시점 정보 유지, 관계는 자료에서 근거가 확인된 경우에만 생성 (9월 보고 표 8)
- 전처리 체계: 대상 선택, 표기 형식 통일, 정형·문서 자료별 구조화 방식 구분 (표 6)
□ 한수원 현장방문 계획 수립
◦ 한수원 내부 자료의 보유 현황과 접근 경로를 조사하기 위해 현장방문(11월 26일 예정)의 조사 항목을 정리하고 방문 일정 협의 (표 9)
- 방문 목적: 한수원 내부 자료의 보유 현황과 접근 경로 조사, 관제시스템 확인, 실무자 확인
- 조사 항목: 보유 자료 범위, 갱신 주기, 제공 방식, 접근 권한, 반출 제한
- 내부 시스템 자료 현황: 댐별 장비·수치 항목(태그)의 규모와 갱신 주기, 항목 부여 규칙과 의미, 활용 가능한 자료의 범위를 조사
- 운영 환경: 외부망 차단 여부 등 시스템 운영 환경과, 법령·규정을 내부에서 검색·갱신하는 방식을 조사
- 태스크 후보 확인: 관제시스템을 확인하여 수행 가능한 태스크 후보를 정리하고, 실무자에게 필요 여부를 확인
- 질문·답변 세트: 태스크 후보에 대응하는 질문 세트를 지참하여 질문의 필요 여부와 답변의 적절성을 확인
3. sLLM 후보군 평가 방향
3.1 후보 모델 조사
□ 국내외 AI·LLM 적용 사례의 기반 모델 조사 및 분석
◦ 수자원 분야를 중심으로 국내외 도메인 특화 LLM 사례에서 기반 모델로 사용된 sLLM을 모델 단위로 조사하여 계열·규모·활용 방식을 정리 (표 10)
- 8월 조사 사례(8월 보고 표 1.2) 중 기반 모델이 명시된 사례를 모델 관점에서 재정리하고, 공학·국내 도메인 사례에서 사용된 sLLM을 추가 조사
◦ ① 계열 — 사례 분석 (표 10)
- Qwen 계열: 수문 특화 모델의 최종 기반 모델로 Qwen2-7B-Instruct가 사용되었고, 공학 해석 설정 자동화에서는 Qwen2.5-7B-Instruct가 기반 모델로 사용됨 [9][14]
- Llama 계열: 수문 QA 미세조정 비교에서 8B Llama 기반 모델이 가장 우수했고, 수자원 지식 과제에서도 Llama3-8B가 기반 모델로 사용됨 [10][11]
◦ Mistral 계열: 국내 보험 금융 도메인 LLM의 기반 모델로 Mistral 7B가 사용되었고, 국내 정비매뉴얼 사례에서는 한국어 적응 모델인 Ko-Mistral이 비교 모델로 사용됨 [15][16]
◦ ① 계열 — 적용 방향
- 여러 사례에서 반복 사용된 Qwen·Llama·Mistral 3개 계열을 후보 계열로 설정
◦ ② 규모 — 사례 분석 (표 10)
- 1.5B~32B 모델 비교에서 8B가 가장 우수했고, 32B는 과적합, 1.5B는 성능이 부족하여 모델 규모와 데이터 규모의 정합이 필요함 [10]
- 약 10B 이하 소형 모델의 미세조정으로 낮은 에너지 비용에서 경쟁력 있는 성능을 낼 수 있고, 236B급 모델 운용에는 A100 GPU 8장이 필요함 [12]
◦ ② 규모 — 적용 방향
- 온프레미스 자원 부담과 도메인 데이터 규모를 고려하여 후보 범위를 7~14B급으로 설정하고, 14B는 한국어 성능 비교를 위한 상한으로 포함 (표 11)
◦ ③ 활용 방식 — 사례 분석 (표 10)
- 경량 미세조정: 7B급 모델에서 DoRA가 LoRA보다 수자원·일반 영역 모두 우수했고, LoRA로 학습 파라미터를 7.6B에서 0.02B로 줄인 7B 모델이 70B급 이상 범용 모델보다 높은 성능을 보임 [9][14]
- 결합 구성: 도구를 호출하는 다중 에이전트, 검증·수정을 수행하는 다중 에이전트, 한국어 임베딩 기반 RAG와 결합 [9][14][16]
◦ ③ 활용 방식 — 적용 방향
- 경량 미세조정 적용성과 도구 호출 대응을 후보 비교 항목에 포함하고, 구조적 적용성은 3.2에서 검토
◦ ④ 운영 환경·한국어 — 사례 분석
- 로컬 배포: A800 GPU로 로컬 추론을 수행하고 vLLM으로 배포함 [9]
- 폐쇄망·한국어: 인터넷이 제한된 환경에서 완전히 온디바이스로 작동하며, 정량 평가와 군 장병 110명의 정성 평가를 종합해 한국어 적응 모델을 최종 선정함 [16]
◦ ④ 운영 환경·한국어 — 적용 방향
- 온프레미스 배치 가능성과 한국어 처리 능력을 별도로 확인하고, 공개 벤치마크 점수로 평가하는 방향으로 3.3 평가체계에 반영
□ 범용 sLLM 후보 모델 조사
◦ 후보 모델 — 특성 분석 (표 11)
- Qwen2.5 7B·14B Instruct: 표·JSON 등 구조화 입출력과 도구 사용 지원이 강화되었고, 개발사 보고 한국어 지표(KMMLU)가 보고된 후보 중 가장 높음 [17]
- Llama 3.1 8B Instruct: 다국어·코딩·추론·도구 사용을 기본 지원하나, 공식 지원 언어에 한국어가 포함되지 않음 [18]
- Mistral 7B Instruct: GQA와 슬라이딩 윈도우 어텐션으로 추론 효율을 높였고 더 큰 Llama 2 13B를 상회하나, 학습 컨텍스트가 8,192 토큰으로 짧음 [19]
3.2 모델 구조 및 특성 검토
□ 검토 방향
◦ GQA, RoPE, SwiGLU, RMSNorm 등 LLM 아키텍처 요소와 토크나이저, 컨텍스트 길이, 양자화, 경량 미세조정(PEFT) 적용성을 후보 모델별로 검토 (표 12)
◦ 구조 요소의 단순 적용 여부보다, 각 요소가 댐 운영 업무의 장문 문서 처리, 응답 속도, GPU 메모리 사용량, 한국어 처리, 수치·표 해석, 근거 기반 응답 안정성에 미치는 영향을 분석하여 모델 선정 시 고려사항으로 정리
□ 구조 요소별 분석 및 적용 방향
◦ ① 어텐션 구조(GQA) — 모델별 특성 분석 (표 12, 표 13)
- GQA [20]: 쿼리 헤드들이 KV 헤드를 공유하여 디코딩 시 KV 캐시 크기를 줄이는 구조로, 세 후보 모두 적용함. KV 헤드 수는 Qwen2.5-7B가 4개로 가장 적음 [17][18][19]
- SWA: Mistral 7B는 고정된 윈도우 안의 토큰만 참조하여 캐시를 W 크기의 순환 버퍼로 유지함 [19]
- KV 캐시 산정: 공개 구조 수치로 산정한 결과, 같은 7~8B급에서도 KV 헤드 수에 따라 토큰당 KV 캐시가 약 2.3배 차이남 (표 13)
◦ ① 어텐션 구조 — 적용 방향
- 장문 근거를 입력할 때 KV 캐시가 GPU 메모리와 응답 속도를 좌우하므로, 입력 길이와 동시 사용자 수 기준의 메모리 산정 결과를 모델 선정 고려사항에 반영
◦ ② 위치 표현·컨텍스트 길이(RoPE) — 모델별 특성 분석 (표 12)
- RoPE [21]: Qwen2.5는 RoPE 기준 주파수를 1,000,000으로, Llama 3는 500,000으로 높여 긴 컨텍스트를 지원함 [17][18]
- 장문 확장: Qwen2.5는 32K까지 학습한 뒤 추론 시 YARN·DCA로 131,072 토큰까지 확장하며, 32K 이내에서는 동작이 바뀌지 않음. Llama 3.1 8B는 128K, Mistral 7B는 학습 컨텍스트 8,192 토큰임 [17][18][19]
- 초장문 성능: 128K 길이에서 Qwen2.5-7B는 14B보다 성능 저하가 큼 [17]
◦ ② 위치 표현·컨텍스트 길이 — 적용 방향
- 매뉴얼·규정 전체를 입력하지 않고 1.3·2.3의 조문 단위 문서 구조화와 연계하여 필요한 조문만 검색해 입력함. 이를 통해 입력을 32K 이내로 유지
◦ ③ FFN 활성화·정규화(SwiGLU, RMSNorm) — 모델별 특성 분석 (표 12)
- Qwen2.5는 SwiGLU와 사전 정규화 방식의 RMSNorm을, Llama 3는 SwiGLU를 적용했고, Mistral 7B는 논문에 기재되지 않음 [17][18][19]
- 검토 관점: SwiGLU는 복합 조건 질의의 응답 안정성, RMSNorm은 긴 답변의 형식 유지·응답 안정성과 관련됨
◦ ③ FFN 활성화·정규화 — 적용 방향
- 확인된 후보 간 같은 구성이므로 구조만으로 차이를 판단하지 않음. 근거 기반 응답 안정성은 3.3 평가에서 실측
◦ ④ 토크나이저 — 모델별 특성 분석 (표 12)
- 어휘 크기와 구성이 후보별로 다름: Qwen2.5는 도구 호출용 제어 토큰을, Llama 3는 비영어 지원 토큰을 추가함 [17][18][19]
- 한국어·수치·단위의 분절 효율은 기술보고서에 보고되지 않음
◦ ④ 토크나이저 — 적용 방향
- 운영규정·방류 기록 표본으로 토큰 수와 수치·단위(EL.m, m³/s 등) 분절 방식을 실측하여 입력 길이·KV 캐시 산정에 반영 (11월)
◦ ⑤ 양자화·경량 미세조정(PEFT) — 특성 분석 (표 12)
- LoRA [22]: 사전학습 가중치를 고정하고 저랭크 분해 행렬만 학습하며, 배포 시 원래 가중치에 병합하여 추가 추론 지연이 없음
- QLoRA [23]: 4-bit 양자화 모델을 고정한 채 LoRA로 학습하여 16-bit 미세조정 성능을 유지함
- 세 후보 모두 구조상 적용 가능하며, 차이는 가중치 메모리 규모에서 발생함(표 12). Qwen2.5는 양자화 버전을 개발사가 함께 제공 [17]
◦ ⑤ 양자화·경량 미세조정 — 적용 방향
- 정밀도(BF16·8-bit·4-bit)별 GPU 메모리, 응답 속도, 한국어·수치 응답 정확도를 온프레미스 조건에서 실측하여 3.3 시스템 성능 항목과 연계 (11월)
- 운영문서 문체, 근거 인용 방식, 표준 응답 형식의 학습 방안은 4.2 경량 미세조정 방식 검토와 연계
◦ 1.3 연계
- KV 캐시 산정과 장문 검토 결과를 1.3 응답 계층 sLLM의 입력 길이(근거 묶음 크기) 설정에 반영
